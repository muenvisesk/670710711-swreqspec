# แผนทางเทคนิค: จองคิวตรวจสุขภาพ (Booking)

อ้างอิง: `SPEC-BKG-001` และ `specs/001-booking/spec.md` สถานะ `Draft v2`

## 1. สรุปแนวทาง

ฟีเจอร์นี้ให้ผู้รับบริการที่ยืนยันตัวตนแล้วเลือกแพ็กเกจ วัน และช่วงเวลาตรวจสุขภาพ (FR-BKG-01, FR-BKG-06)
ระบบจะแสดงช่วงเวลาที่ว่างและจำนวนที่นั่งคงเหลือภายใน 30 วัน (FR-BKG-01)
ระบบตรวจคิวเดิม ป้องกันการจองซ้ำ และจัดการกรณีช่วงเวลาเต็มระหว่างการยืนยัน (FR-BKG-02, FR-BKG-03)
เมื่อจองสำเร็จ ระบบบันทึกการจอง ตัดที่นั่ง ออกหมายเลขคิว และส่งคำขอแจ้งเตือนแบบ asynchronous (FR-BKG-04, IF-NOT-01)
การส่งข้อความล้มเหลวต้องไม่ทำให้การจองหาย และต้องนำงานเข้าสู่คิวส่งซ้ำภายใน 5 นาที (FR-BKG-05, NFR-REL-02)

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React (Vite) | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สร้างหน้าจอค้นหาช่วงเวลาและยืนยันการจอง |
| Python FastAPI | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สร้าง API สำหรับการค้นหาและยืนยันการจอง |
| MySQL | CON-TECH-01 | ใช้จัดเก็บข้อมูลการจอง ช่วงเวลา คิวแจ้งเตือน และ audit log |
| TLS 1.2 ขึ้นไป | NFR-SEC-01 | ใช้กับการรับส่งข้อมูลการจองตามขอบเขตการเชื่อมต่อของระบบ |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| PatientReference | `hn`, สถานะผลยืนยันตัวตน | IF-IDP-01, IF-HIS-01 |
| Package | `package_id`, ข้อมูลแพ็กเกจที่ใช้เลือกบริการ | FR-BKG-06 |
| TimeSlot | `slot_id`, วันที่, เวลาเริ่มต้น, เวลาสิ้นสุด, โควตา, จำนวนที่นั่งคงเหลือ, เงื่อนไขแพ็กเกจ | FR-BKG-01, FR-BKG-03, FR-BKG-06, ASM-01 |
| Booking | `booking_id`, `hn`, `package_id`, `slot_id`, สถานะการจอง, `queue_number`, เวลาที่สร้าง | FR-BKG-02, FR-BKG-04, FR-BKG-05 |
| NotificationOutbox | `booking_id`, ช่องทาง SMS/LINE, สถานะการส่ง, เวลาส่งครั้งถัดไป | FR-BKG-04, FR-BKG-05, IF-NOT-01, NFR-REL-02 |
| AuditLog | ผู้เข้าถึง, เวลาที่เข้าถึง, `hn` | DOM-PDPA-01, AC-BKG-06 |

ระบบรับเลขบัตรประชาชนเพื่อค้นข้อมูลจาก HIS ตาม IF-HIS-01 ได้เฉพาะระหว่างการเรียกใช้งาน และจะไม่เก็บเลขบัตรประชาชนใน `Booking` หรือ entity การจอง (IF-HIS-01)

## 4. API / หน้าจอ

- `GET /booking/availability` รับ `package_id` และช่วงวันที่, ส่งรายการวัน ช่วงเวลา และจำนวนที่นั่งคงเหลือ (FR-BKG-01, FR-BKG-06)
- `POST /booking/confirm` รับ `hn`, `package_id` และ `slot_id`, ส่งผลสำเร็จพร้อมหมายเลขคิวหรือผลปฏิเสธ/ช่วงเวลาเต็ม (FR-BKG-02, FR-BKG-03, FR-BKG-04, FR-BKG-05)
- หน้าค้นหาและเลือกช่วงเวลา แสดงช่วงเวลาที่ว่าง จำนวนที่นั่ง และคำนวณรายการใหม่เมื่อเปลี่ยนแพ็กเกจ (FR-BKG-01, FR-BKG-06)
- หน้ายืนยันการจอง แสดงผลสำเร็จพร้อมหมายเลขคิว หรือแจ้งคิวเดิม/ช่วงเวลาเต็มตามผลการยืนยัน (FR-BKG-02, FR-BKG-03, FR-BKG-04, FR-BKG-05)
- กระบวนการส่ง `NotificationOutbox` แบบ asynchronous รับคำขอหลังบันทึกการจอง และจัดส่งซ้ำตามกำหนด (IF-NOT-01, NFR-REL-02)
- กระบวนการตรวจสิทธิ์ก่อนเข้าถึงข้อมูลผู้รับบริการ ต้องได้รับผลจาก IDP ก่อน และค้นข้อมูลอ้างอิงด้วย HN จาก HIS (IF-IDP-01, IF-HIS-01)

## 5. ตารางตรวจ Constraints

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| CON-TECH-01 | ใช้ MySQL ในโมเดล `Booking`, `TimeSlot`, `NotificationOutbox` และ `AuditLog` (หัวข้อ 2, 3) | ใช้แล้ว |
| DOM-PDPA-01 | บันทึก `AuditLog` ทุกครั้งที่เข้าถึงข้อมูลสุขภาพ โดยมีผู้เข้าถึง เวลา และ HN และเก็บไม่น้อยกว่า 1 ปี (หัวข้อ 3) | ใช้แล้ว |
| IF-IDP-01 | ตรวจผลยืนยันตัวตนก่อนกระบวนการค้นข้อมูลและการจอง (หัวข้อ 4) | ใช้แล้ว |
| IF-HIS-01 | ค้นข้อมูลจาก HIS ด้วยเลขบัตรประชาชน ใช้ HN ภายในระบบ และไม่เก็บเลขบัตรประชาชนใน `Booking` (หัวข้อ 3, 4) | ใช้แล้ว |
| IF-NOT-01 | สร้าง `NotificationOutbox` และส่งคำขอ SMS/LINE แบบ asynchronous หลังการจอง (หัวข้อ 3, 4) | ใช้แล้ว |

## 7. ลำดับงาน

1. กำหนดโครงสร้างข้อมูล `PatientReference`, `Package`, `TimeSlot`, `Booking`, `NotificationOutbox` และ `AuditLog` ตามข้อจำกัดการไม่เก็บเลขบัตรประชาชน (IF-HIS-01, DOM-PDPA-01)
2. สร้างขั้นตอนตรวจผล IDP และค้นข้อมูลผู้รับบริการจาก HIS ก่อนเข้าถึงข้อมูล (IF-IDP-01, IF-HIS-01)
3. สร้าง API และหน้าจอแสดงวัน ช่วงเวลา และจำนวนที่นั่ง พร้อมการคำนวณใหม่เมื่อเปลี่ยนแพ็กเกจ (FR-BKG-01, FR-BKG-06)
4. สร้างการตรวจคิวเดิมและการยืนยันการจอง พร้อมตัดที่นั่งและออกหมายเลขคิว (FR-BKG-02, FR-BKG-04, AC-BKG-01, AC-BKG-02)
5. สร้างการตรวจช่วงเวลาเต็มระหว่างยืนยัน โดยไม่สร้างรายการจองและแสดงตัวเลือกที่รวมวันถัดไป (FR-BKG-03, AC-BKG-03)
6. สร้างการส่งคำขอ SMS/LINE แบบ asynchronous และจัดการงานส่งซ้ำ (FR-BKG-05, IF-NOT-01, NFR-REL-02, AC-BKG-04)
7. เพิ่มการบันทึก audit log และตรวจการเข้ารหัสการรับส่งข้อมูล (DOM-PDPA-01, NFR-SEC-01, AC-BKG-06)
8. ทดสอบประสิทธิภาพและความสำเร็จของทุก acceptance criteria ตามตาราง (NFR-PERF-01, NFR-USE-01, AC-BKG-01 ถึง AC-BKG-06)
